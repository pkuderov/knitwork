# GridRnnMultimodal

Модель для бенчмарка Multimodal Digit-Sum (MDS): проверяет, может ли GridRNN научиться **маршрутизировать разные модальности по разным столбцам** и **выборочно игнорировать столбцы-дистракторы** — в отличие от базовой `GridRnn`, где реальный вход получает только нулевой столбец, а остальные видят лишь фиктивный ноль и общаются исключительно через attention. Задача: два "сигнальных" столбца получают цифру-изображение (MNIST) и цифру-аудио (FSDD) в разные, разреженные по времени моменты; остальные столбцы — "буферные", получают чистый гауссов шум каждый шаг. По сигналу `query` сеть должна выдать текущую накопленную сумму всех цифр, пришедших с начала эпизода — аналог store/query механики SDQ, но распределённый по столбцам вместо одного потока токенов.

## Ключевой механизм

Каждый столбец слоя 0 получает **свою** линейную проекцию входа вместо единого `nn.Embedding` по токенам и вместо dummy-нуля для "лишних" столбцов:

```python
def _prepare_grid_input(self, image_feat, audio_feat, buffer_feat):
    xl = [None] * self.n_columns
    xl[self.signal_columns[0]] = self.image_proj(image_feat)
    xl[self.signal_columns[1]] = self.audio_proj(audio_feat)
    for j, ix_col in enumerate(self.buffer_columns):
        xl[ix_col] = self.buffer_proj(buffer_feat[:, j])
    return xl
```

Отличить "полезный" столбец от буферного сеть может только по обучаемым column identities в `MessagePassingLayer` (переиспользуется из `grnn.py` без изменений) — поэтому `col_identities=True` обязателен, это единственный канал, через который attention узнаёт "какой я столбец".

Выходная голова читает не фиксированный столбец 0, а усреднение по обоим сигнальным столбцам верхнего слоя — ответ не привязан к конкретному столбцу, поскольку модальностей две:

```python
z = h[-1, self.signal_columns, :, :].mean(dim=0)
y = self.head(z)
```

## Baseline "naive concat"

Для проверки, что именно поколоночная маршрутизация даёт выигрыш (а не просто более широкий вход), в модели предусмотрен вырожденный режим: если `signal_columns = [0, 0]`, обе модальности складываются в один и тот же столбец —

```python
if self.signal_columns[0] == self.signal_columns[1]:
    xl[self.signal_columns[0]] = self.image_proj(image_feat) + self.audio_proj(audio_feat)
```

Это аналог небезопасных ("non-selective") SSM-бейзлайнов из статьи Mamba на задаче selective copying (~57-60% против ~99.8% у selective-механизма) — ожидается, что при росте числа буферных столбцов и уровня шума этот режим проигрывает полноценной поколоночной маршрутизации.

## Гиперпараметры

| Параметр | Описание |
|---|---|
| `signal_columns` | пара индексов столбцов для image/audio; `[c, c]` — вырожденный concat-baseline |
| `n_columns` | всего столбцов; буферных = `n_columns - 2` (должно совпадать с `n_buffer_columns` генератора) |
| `buffer_feat_dim` | размерность шумового вектора буферных столбцов (по умолчанию `max(image_feat_dim, audio_feat_dim)`) |
| `col_identities` | обязателен `True` — иначе столбцы неразличимы для attention |
