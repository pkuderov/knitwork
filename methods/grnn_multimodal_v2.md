# GridRnnMultimodalV2

Версия 2 [[grnn_multimodal]], исправляющая две проблемы, найденные при анализе реального прогона на бенчмарке Multimodal Digit-Sum:

1. **Буферные столбцы не были архитектурно изолированы** — attention-heatmap показал, что на верхнем слое сигнальный столбец, формирующий ответ, всё ещё уделял буферному столбцу заметное внимание (~0.45), хотя абляция подтверждала, что *шум* из буфера не влияет на точность. То есть сеть научилась игнорировать содержимое буфера, но не была вынуждена архитектурно этого делать — буферные столбцы использовались как "ретранслятор" полезного сигнала.
2. **`mean-pool` двух сигнальных столбцов мог гасить информацию** — `col_sim/signal_signal` в реальном прогоне монотонно уходил в отрицательную зону (~-0.2..-0.3): два сигнальных столбца (image/audio) специализировались в разные, анти-коррелирующие представления. Усреднение двух почти противофазных векторов частично взаимоуничтожается.

## Ключевой механизм

**Hard-gated изоляция буфера**: вместо обычного `MessagePassingLayer` из `grnn.py`, здесь `MaskedMessagePassingLayer` получает булеву маску attention, которая структурно запрещает сигнальным столбцам делать query к буферным на любом слое:

```python
attn_mask = torch.zeros(n_columns, n_columns, dtype=torch.bool)
for sc in self.signal_columns:
    for bc in self.buffer_columns:
        attn_mask[sc, bc] = True   # sc не может attend к bc

h_mixed, attn_w = self.mha(qh, kh, vh, attn_mask=self.attn_mask, average_attn_weights=True)
```

Буферные столбцы по-прежнему могут attend куда угодно (это не важно — их состояние никогда не используется в голове), но обратного пути "буфер → сигнал" через attention больше не существует ни на одном слое.

**Concat вместо mean-pool** в голове — оба сигнальных столбца конкатенируются, а не усредняются, так что даже анти-коррелирующие представления не гасят друг друга:

```python
z = torch.cat([h[-1, sc0], h[-1, sc1]], dim=-1)   # [B, 2*hidden]
y = self.head(z)                                    # nn.Linear(2*hidden, output_size)
```

## Диагностика "где сеть считает сумму"

Помимо визуализаций из v1 (attention heatmap, confusion matrix, column similarity), общий раннер (`run_multimodal_sum.py`) теперь также логирует:

- **CKA между столбцами** (`knitwork.visualization.cka.CKAVisualizer`, переиспользован из SDQ) — насколько похожи представления разных столбцов на каждом слое.
- **`sum_probe_r2`** — на каждом снапшоте обучается closed-form ridge-регрессия из скрытого состояния каждого `(layer, column)` в текущую истинную сумму (`gen.sum_now`, а не только на query-шагах), и логируется R². Показывает, в каком слое/столбце линейно "живёт" информация о накопленной сумме — heatmap `viz/sum_probe_r2` и скаляры `sum_probe_r2/L{l}_C{c}`.
