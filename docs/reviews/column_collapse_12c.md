## 1. Что было найдено в baseline

Из 12 колонок задачу решали **три**. Остальные девять были причинно пустыми:
удаление любой из них меняло точность на ≤0.025.

- `causal drop`: C0 = **0.791**, C1 = 0.126, C2 = 0.068, все остальные ≤ 0.025
- `logit_share`: C0 = 0.68, C1 = 0.32, у остальных **ровно 0**
- CKA: C3–C8 и C11 образовали единый блок с попарными **0.51–0.83**
- эффективное число колонок (exp энтропии нормированных вкладов) = **2.68**

Причём C0 оказалась не «важной колонкой», а всем трактом вывода: кривая `-C0`
шла плоско на 0.16 **независимо от gap** — без неё памяти не оставалось вообще.

### Два подводных камня в самой диагностике

**Probe-heatmap читается неверно без базовых уровней.** Столбцы `stored_val` (~0.66
во всех колонках) и `net_count` (~0.54) выглядят информативными, но это в точности доля
мажоритарного класса (0.659 и 0.535) — зонд выучил константу. Реальная информация есть
только в `queried_key` (база 0.20) и `target` (база 0.285).

**Прокси-метрики важности не работают.** `attn_centrality` назвал бы главной C9 (0.17,
выше C0 и C1), хотя её удаление стоит 0.025 против 0.791 у C0. `act_norm` менялся всего
в 1.34× при разбросе причинного вклада от 0 до 0.79. Согласованы между собой только
`causal_drop`, `marginal_value`, `readout_single` и (в коллапсировавшей модели)
`logit_share`.

## 2. Диагноз: регуляризация не работала

Найдены **два независимых дефекта**, из-за которых оба механизма декорреляции колонок
были фактически выключены.

### 2.1. `optim` молча обнулял activation-loss

```python
if optim:
    # optimized variant drops the activity-decorrelation aux loss
    self.aux_act_weight = 0.0
```

Конфиг объявлял `aux_act_weight: 0.02`, в Comet логировалось 0.02, до лосса доходил 0.
Это единственный терм, штрафующий **синхронное обновление** колонок:

```python
u = (hl_n - hl).norm(dim=-1)          # [C, B] величина обновления колонки
u = (u - u.mean(1, keepdim=True)); u = u / (u.norm(1, keepdim=True) + 1e-6)
act = F.relu((u @ u.T)[iu, ju]).mean()
```

Barlow-терм `div` давит корреляцию **состояний**, но не мешает колонкам обновляться
в унисон — то есть ровно наблюдавшийся режим отказа ничем не штрафовался.

### 2.2. Расписания aux считались не в тех единицах

`_aux_tick` инкрементируется **раз на forward-вызов**, а `step += gen.n_envs` — то есть
один тик соответствует 128 env-шагам. При этом `aux_div_ramp_steps` задаётся в env-шагах,
как `n_steps`. Итог — ramp короче задуманного в `n_envs` раз:

| прогон | `aux_div_ramp_steps` | тиков за 61M | frac в конце | доля номинала |
|---|---|---|---|---|
| baseline | 2e7 | 476 562 | 0.024 | **2.4%** |
| REG | 1e7 | 476 562 | 0.048 | **4.8%** |

Barlow-терм за весь прогон не поднялся выше 5% номинального веса. Это объясняет,
почему `col_sim/max` не сдвинулся (0.476 → 0.489) и почему ужесточение `aux_div`
в прогоне REG ничего не дало: **весь наблюдавшийся эффект дал `aux_act`**.

---

### 2.3. Счётчик aux вообще не шёл при `optim: true` — все пять арок недействительны

Найдено 2026-07-28 при отладке `grnn_redo`. Самый серьёзный из трёх дефектов.

`grid_step` увеличивал `_aux_tick` под условием:

```python
if not self.grad_checkpoint or not torch.is_grad_enabled():
    self._aux_tick += 1
```

Комментарий рядом утверждал, что `torch.utils.checkpoint(..., use_reentrant=False)`
выполняет исходный проход под `no_grad`, а перевычисление — под `enable_grad`, поэтому
условие якобы пропускает инкремент ровно один раз. **Это верно для реентрантной
реализации, а не для `use_reentrant=False`**: там оба прохода идут с включённым градиентом.

Следствие при `grad_checkpoint = optim = true` (то есть во всех 12C-арках):

- `_aux_tick` **навсегда оставался 0**;
- `_aux_scale()` возвращал `0 / ramp = 0`, то есть `aux_div`, `aux_div_max` и `aux_act`
  умножались на ноль **весь прогон**;
- `do_aux` = `(0 % 8 == 0)` = `True`, поэтому aux считался каждый шаг, а множитель
  `aux_every = 8` завышал вес оставшихся (нескалируемых) термов — gate, sat, head — в 8 раз.

Проверено прямым замером: при `optim: false` счётчик идёт (1024, 21504, 41984 env-шагов),
при `optim: true` остаётся 0 на протяжении 2e5 шагов.

**Что это значит для разделов 3–3b.** Все выводы про `aux_act`, Barlow-терм и расписание
`ramp → hold → decay` относятся к термам, которые были равны нулю. В частности:

- baseline и REG различались в конфиге только весом `aux_act` (0.02 против 0.04) — оба
  занулены, то есть **эффективно это два прогона с одинаковым лоссом и разными сидами**.
  Разница между ними (max Δ 0.791 против 0.344) — оценка разброса от прогона к прогону,
  а не эффект регуляризации. Все сравнения в разделе 3a надо читать с этой поправкой.
- Реально различались только `aux_head_weight` (0 / 0 / 0 / 0.05 / 0.15 по аркам) и сид.
- Вывод 2.2 про «Barlow работал на 2.4% номинала» неверен количественно: он работал на 0%.

Наблюдение из раздела 3b о том, что структура застывает к 0.6M шагов, **остаётся в силе** —
оно получено из кривых `col_cka`, а не из значений весов. Но его объяснение меняется:
дело не в том, что рамп до 1e7 приходит поздно, а в том, что он не приходит вообще.

**Исправление.** Часы aux теперь ведёт цикл обучения, а не модель:

```python
def set_env_step(self, step: int, aux_on: bool = True) -> None:
    self._ext_clock = True
    self.aux_tick_scale = 1
    self._aux_tick.fill_(int(step))
    self.aux_on = aux_on
```

`aux_on` выставляется **на весь rollout**, а не на шаг: backward перевычисляет все
`rollout_len` чекпоинтнутых шагов разом, и если флаг переключится посередине, сохранённое
число тензоров в проходах разойдётся (`CheckpointError`). Это же исправляет и множитель
`aux_every`: теперь aux действительно срабатывает один rollout из восьми.

**Практическое следствие: нужен новый референс.** Ни одну из пяти арок нельзя сравнивать
с прогонами после фикса. `grnn_fix_v4_12c_reg2` следует перезапустить как эталон.

## 3. Результат прогона REG

Веса: `aux_act 0 → 0.04`, `aux_div 0.05 → 0.08`, `aux_div_max 0.1 → 0.15`,
ramp 2e7 → 1e7 (последние три, как теперь известно, почти без эффекта).

### Стало лучше

| метрика распределённости | baseline | REG |
|---|---|---|
| max causal delta | 0.791 | **0.344** |
| колонок с delta ≥ 0.05 | 3 / 12 | **7 / 12** |
| эффективное число колонок | 2.68 | **8.01** |
| CKA off-diag mean / max | 0.429 / 0.83 | 0.391 / 0.79 |
| пар с CKA > 0.6 | 18 / 66 | 13 / 66 |
| колонок с selectivity > 0.2 | 1 | 3 |

Единая точка отказа исчезла: `-C0` теперь идёт 0.51 → 0.29 и **сохраняет зависимость
от gap** — модель без главной колонки работает как деградировавшая, но живая память.

Точность на фиксированном `hard` не пострадала: **0.948 → 0.952**
(CI [0.950, 0.955] против [0.946, 0.950]), query 0.884 → 0.888, distract 0.988 → 0.992.
Короткие разрывы лучше: `[0,2)` 0.922→0.930, `[4,8)` 0.894→0.902, `[8,16)` 0.849→0.855.

### Стало хуже

- **Длинные разрывы**: `[16,32)` 0.751 → **0.719** (n=907, не шум). Бин `[32,64)` при
  n=44 непригоден для выводов.
- **Curriculum замедлился**: `curr_step` 107 → **95**, при этом train `Acc` 0.927 → 0.873.
  Проверено по Comet: REG учился на *более лёгком* распределении (`gen/ep_lens` 20.5 → 19.4,
  `gen/sq_gaps` 8.90 → 8.66) и всё равно показывал там меньшую точность. То есть на
  усложнённом распределении baseline честно сильнее.
- **Линейная декодируемость обрушилась**: full-set probe `target` 0.820 → 0.679, лучшая
  одиночная колонка 0.706 → 0.469, лучшая тройка 0.801 → 0.603, `keep[0,6,8]`
  0.403/0.311 против 0.760/0.644. Это ожидаемая обратная сторона распределённости.
- **Голова осталась воронкой**: `logit_share` C1 = **0.81** при causal delta C1 = 0.138.
  В baseline logit_share и causal_drop согласовывались, теперь противоречат — pooled-голова
  (`optim=True` усредняет колонки) гонит логит через одну колонку, а остальные
  компенсируют потерю через рекуррентность.
- **Остатки коллапса**: C3 и C7 мертвы (delta 0.003 / 0.001), кластер {C2, C5, C7, C9}
  держится на 0.70–0.79.

### Голова, зонды, curriculum

Две разные метрики монополии головы, которые легко перепутать:
`argmax_share` — доля запросов, где данная колонка даёт наибольший вклад в верный логит;
`mag_share` — доля колонки в сумме `mean |contrib|`. **`aux_head` оптимизирует именно
`mag_share`**, поэтому судить об эффекте терма нужно по нему.

| прогон | max `argmax_share` | max `mag_share` | эфф. колонок головы | full-set probe `target` | min-sufficient | `curr_step` |
|---|---|---|---|---|---|---|
| baseline | C0 0.682 | 0.484 | 4.08 | 0.820 | `[0,1,2]` 0.801 | 107 |
| REG | C1 **0.810** | 0.417 | 4.16 | 0.679 | `[0,6,8]` 0.603 | 95 |
| ACT-only | C0 0.662 | 0.436 | 5.95 | 0.713 | `[1,7,11]` 0.601 | 99 |
| REG2 | C2 **0.558** | 0.285 | **7.43** | **0.837** | `[2,4,7]` 0.795 | 100 |
| robust | C3 0.585 | **0.271** | 7.10 | 0.789 | `[0,2,3]` 0.832 | — |

### Что из этого следует

**REG2 выиграл по всем показателям качества**, включая длинные разрывы. Гипотеза про
`ramp → hold → decay` подтвердилась: регрессия REG на `[16,32)` (0.751 → 0.719) не просто
снята, а обращена в улучшение до **0.797**. Curriculum частично разблокирован (95 → 100),
хотя baseline'ских 107 не достиг — при этом на фиксированном распределении REG2 сильнее.

**Barlow-терм ухудшает CKA, но улучшает причинную устойчивость.** ACT-арка с полностью
выключенным div дала лучшую декорреляцию из всех: CKA mean 0.325, max 0.69, 5 пар из 66
выше 0.6. А REG2, где div впервые отработал на полном весе, показал одну из худших
CKA (0.517) — и при этом лучший max Δ (0.256).

> Первая редакция этого раздела гласила «Barlow не нужен и, похоже, вреден» — вывод был
> сделан по CKA, то есть по метрике, которую тот же раздел ниже объявляет неправильной
> целью. Арка `robust` (раздел 3b) сняла div полностью и получила max Δ 0.380 против
> 0.256, что подтверждает: по целевой метрике div скорее **нужен**.

**Низкая CKA не является целью.** ACT с лучшей декорреляцией имеет худшую точность (0.933)
и **хрупкую** структуру: Σ причинных вкладов 2.26, удаление C0 стоит 0.581, C1 — 0.566,
C2 — 0.328, C7 — 0.301. Колонки несут уникальную информацию, поэтому потеря любой из
нескольких почти фатальна. У REG2 наоборот: избыточные представления дают резервирование,
максимальный вклад одной колонки всего 0.256, модель переживает удаление любой.

То есть **избыточность = резервирование**. Проблема baseline была не в избыточности как
таковой, а в том, что девять колонок были одновременно избыточными **и** причинно пустыми.

**Head-терм работает, но насыщается.** `aux_head_weight=0.05` сбил `mag_share` с 0.417 (REG)
до 0.285 (REG2) при цели `2/C` = 0.167. Утроение веса до 0.15 в арке `robust` дало
0.271 — то есть почти ничего (см. раздел 3b: терм упирается не в вес, а в свою форму).

**Новый детектор `col_cka` состоятелен.** На финальном шаге: ACT `col_cka/max` = 0.654,
REG2 = 0.916 — порядок совпадает с оффлайн-анализом (0.69 и 0.86). Старый `col_sim/max`
на паре baseline/REG показывал 0.476 против 0.489, то есть **противоположный** порядок
относительно CKA 0.83 против 0.79.

**Специализация и причинная важность разошлись.** В REG2 колонка C3 стала выделенным
носителем ключа запроса — `queried_key` = **0.992**, лучшая selectivity в сети (0.429) —
но её удаление стоит всего 0.008. Чистый пример того, что интерпретируемая специализация
не означает причинной необходимости.

## 3b. Арка `robust`: отрицательный результат

Новая модель `knitwork/models/grnn_robust.py` (`GridRnnRobust(GridRnnFixV4)`, 60 строк)
с column dropout — обучающим аналогом причинной абляции, которую делает оффлайн-анализ.
Гипотеза: если любую колонку можно выключить **во время обучения**, ни одна не станет
единой точкой отказа на инференсе.

### Гипотеза не подтвердилась

`robust` хуже `REG2` по каждой оси: Acc 0.955 против 0.962, max Δ 0.380 против 0.256,
эфф. колонок 6.16 против 8.53, CKA mean 0.552 против 0.517 и **28 пар из 66** выше 0.6 —
худший показатель избыточности среди всех пяти арок.

### Ошибка постановки эксперимента

Относительно REG2 менялись **четыре** параметра одновременно:

| | REG2 | robust |
|---|---|---|
| `aux_div_weight` | 0.05 | 0 |
| `aux_div_max_weight` | 0.25 | 0.1 |
| `aux_head_weight` | 0.05 | 0.15 |
| `col_dropout` | — | 0.1 |

Поэтому «виноват dropout» — гипотеза с механизмом, а не установленный факт. Ослабление
div в 2.5–∞ раз не менее правдоподобно, тем более что арка ACT-only (div выключен)
тоже дала плохой max Δ = 0.581. Два из пяти прогонов без сильного div — два худших
результата по целевой метрике.

### Что получилось структурно: два яруса

- **C0, C3** — специалисты. Probe на `target`: 0.658 и 0.747 при базовой ставке 0.285.
  Вся причинная масса: Δ = 0.306 и 0.380. `argmax_share` C3 = 0.585.
- **C4–C11** — восемь взаимозаменяемых пустышек. Probe на `target` 0.31–0.38, то есть
  на уровне majority-class. Δ ≤ 0.086, у четырёх из них Δ ≤ 0.013.
  Весь высокий CKA — между ними: C4–C8 0.86, C5–C9 0.81, C1–C8 0.77.

### Механизм: dropout и mean-pooling тянут в разные стороны

При `pooled_head=True` голова видит среднее по колонкам. Dropout требует, чтобы верный
ответ давало среднее по **случайному подмножеству**. Дешевле всего это удовлетворить,
сделав droppable-колонки одинаковыми и безвредными, а содержательные оставив как есть:
при `p=0.1` C0 и C3 почти никогда не выпадают одновременно, и модель просто терпит
редкие потери.

То есть dropout наказывает специализацию тех колонок, которые он выбивает, вместо того
чтобы её требовать. Это объясняет одновременно рост CKA (28/66) и падение эфф. колонок
(6.16): восемь клонов плюс два незаменимых специалиста.

### Побочный результат: `_head_aux` упирается в форму, а не в вес

Утроение `aux_head_weight` (0.05 → 0.15) сдвинуло `mag_share` всего с 0.285 до 0.271,
а эфф. число колонок головы даже снизилось (7.43 → 7.10). Причина в формуле:

```python
return F.relu(share.max() - self.head_share_target)   # штрафуется ТОЛЬКО максимум
```

Градиент идёт лишь в одну колонку — текущий максимум. Терм срезает верхушку, но не
может поднять хвост: как только лидер сравнялся со вторым, штраф выключается, а десять
колонок с долей ~0.01 остаются как были. Это «whack-a-mole»-штраф. Варианты формы,
которые не насыщаются: сумма `relu` по всем колонкам, либо энтропия распределения
`share` вместо максимума.

## 4. Внесённые изменения

### `knitwork/models/grnn_fix_v4.py`

- убрано принудительное `aux_act_weight = 0.0` при `optim=True`
- `aux_tick_scale` — расписания aux переведены в env-шаги (run-скрипты ставят `gen.n_envs`)
- `_aux_scale()` — огибающая **ramp → hold → decay** (`aux_hold_steps`, `aux_decay_steps`,
  `aux_final_frac`), применяется и к div, и к act. По умолчанию `decay_steps=0` = прежнее
  поведение
- `pooled_head` развязан с `optim` — можно взять concat-голову при включённых оптимизациях
- `aux_head_weight` + `_head_aux()` — штраф за монополизацию логита одной колонкой:
  `relu(max_share - head_share_target)`, дефолт цели `2/C`

### `knitwork/exps/sdq/run_sdq.py`, `knitwork/exps/text/run_text.py`

- проставляют `rnn.aux_tick_scale = gen.n_envs`
- `log_col_cka()` — попарная CKA по колонкам во время обучения (`col_cka/max`, `/mean`,
  `/frac_gt_06`). Существующий `col_sim` сравнивает **усреднённые по батчу** активации
  и коллапс не поймал; CKA считает ту же величину, что и оффлайн-анализ

### `inference/analyze_columns_sdq.py`

- `--n_collect` по умолчанию 800 → **4000**: при 800 в бине `[32,64)` было 44 примера,
  то есть самый интересный участок кривой измерялся шумом
- палитра `turbo` вместо дефолтного цикла из 10 цветов — при 12 колонках `-C0`/`-C10`,
  `-C1`/`-C11`, `-C2`/`keep` сливались
- `pooled_head` вместо `optim` при разборе головы (со совместимостью со старыми чекпоинтами)

### `knitwork/exps/sdq/config/extend_config.yaml`

- `grnn_fix_v4_12c_reg` — прогон, описанный выше
- `grnn_fix_v4_12c_act` — арм атрибуции: `aux_act=0.04`, Barlow-термы **полностью выключены**
  (`aux_div_weight=0`, `aux_div_max_weight=0`). Оставить у div «baseline-значения» было бы
  бессмысленно: после фикса единиц они впервые означают полный вес, а не 2.4% от него,
  так что изоляция достигается только обнулением
- `grnn_fix_v4_12c_reg2` — следующая итерация: decay после 35M до 0.3×, `div_max` 0.25
  точечно по худшей паре, `div_latent_dim=44` + `aux_batch_frac=0.5` (чистая оценка Barlow),
  `aux_head_weight=0.05`

Все три варианта — ровно **388.41K параметров**: aux-веса безразмерные, `div_proj`
зарегистрирован как buffer.

⚠️ Снятие обнуления `aux_act` затрагивает и другие конфиги с `optim: true`
(`grnn_fix_v4_2m`, `grnn_fix_v4_10m` в sdq и text, два блока в `text/config/large.yaml`) —
у них activation-loss теперь тоже включится, и старые запуски с новыми напрямую несравнимы.

## 5. Основные выводы

1. **Коллапс колонок лечится, и почти бесплатно по точности.** Эффективное число колонок
   2.68 → 8.01 при точности 0.948 → 0.952. Оверпровижининг на 12 колонок сам по себе
   не проблема — проблема в отсутствии давления на декорреляцию.

2. **Штрафовать нужно синхронность обновлений, а не корреляцию состояний.** Подтверждено
   прямой абляцией: ACT-арка **без Barlow-терма вообще** даёт лучшую декорреляцию (CKA
   mean 0.325 против 0.517 у REG2 с полностью рабочим div). Весь эффект даёт `aux_act`;
   Barlow при рабочем весе сопровождается ростом CKA, а не падением.

2a. **Избыточность — это резервирование, а не дефект.** Минимизировать CKA как самоцель
   вредно: ACT с лучшей CKA хрупок (Σ причинных вкладов 2.26, четыре колонки с Δ > 0.3),
   REG2 с худшей CKA робастен (max Δ = 0.256). Правильная цель — низкий **максимальный
   причинный вклад** при сохранённой избыточности, а не низкая попарная схожесть.

3. **«Каждая колонка бесполезна» ≠ «колонки бесполезны».** В baseline сумма одиночных
   вкладов C3–C11 = 0.083, а одновременное удаление = 0.188 (сверхаддитивность ×2.3).
   Судить о ненужности колонок по одиночным абляциям нельзя.

4. **Probing и абляция измеряют разное.** В baseline линейный readout насыщался
   на трёх колонках (0.801 = full), но модель на этих трёх работала на 0.644 по запросам.
   Зонд смотрит на неповреждённую модель в один момент, абляция ломает рекуррентность
   на всём роллауте — «лишние» колонки нужны как динамика, а не как хранилище.

5. **Постоянное давление регуляризации стоит длинной памяти.** Регрессия на `[16,32)`
   и замедление curriculum — плата за то, что вес держится до конца обучения. Схема
   ramp → hold → decay подтверждена: `[16,32)` 0.719 → **0.797**, что выше и baseline (0.751).

6. **Метрики важности расходятся, и по-разному в разных режимах.** `act_norm` и
   `attn_centrality` бесполезны всегда. `logit_share` был надёжен в коллапсировавшей
   модели и стал вводить в заблуждение в распределённой. Доверять можно
   `causal_drop` + `marginal_value` + `readout_single`.

7. **Онлайн-детектор коллапса нужен обязательно.** `col_sim/max` не поймал ни коллапс,
   ни его исправление и на паре baseline/REG дал порядок, обратный CKA. Заменён на
   `col_cka/*`, который на паре ACT/REG2 воспроизвёл оффлайн-результат.

8. **`aux_act` дёшев и должен быть включён по умолчанию.** Единственный терм, дающий
   измеренный выигрыш, стоит одного `[C,B]`-норма на aux-шаг и был выключен полтора года
   из-за оптимизации памяти, которая его не касалась.

## 6. Итоговая рекомендация по конфигу

Лучшая известная точка после пяти арок — по-прежнему **`grnn_fix_v4_12c_reg2`**, без
изменений. Рекомендация из первой редакции этого раздела (снять `aux_div`, поднять
`aux_head` до 0.15) была проверена аркой `robust` и **отклонена**: снятие div ухудшило
max Δ, а утроение `aux_head` не дало почти ничего.

## 7. Что проверять дальше

**Проверено и закрыто:** атрибуция эффекта к `aux_act` (арм ACT), польза decay (арм REG2),
работоспособность `col_cka`, статистика на длинных разрывах при `n_collect=4000`,
column dropout при mean-pooled голове (арм `robust` — вреден),
`aux_head_weight` 0.05 → 0.15 (насыщение, выигрыша нет).

**Открыто:**

- **чистая изоляция `aux_head=0.15`** — арка `robust` меняла четыре параметра сразу;
  если нужен вывод именно про head-терм, повторить от REG2 с одним изменением
- **`_head_aux` через энтропию или сумму `relu`** вместо `relu(max)` — текущая форма
  насыщается, как только лидер сравнялся со вторым
- **concat-голова** (`grnn_robust_concat`, `pooled_head: false`) — прямая проверка
  механизма из 3b: при своём куске readout у каждой колонки среднее подменить нечем,
  и dropout должен работать в нужную сторону
- **структурный dropout** — ронять top-1 по вкладу вместо случайных 10%; при `p=0.1`
  случайный dropout почти никогда не выбивает обоих специалистов сразу
- **метрики матрицы внимания** — ни одна из пяти арок не смотрела на маршрутизацию:
  `attn/diag_frac`, максимальная входящая доля, энтропия. Двухъярусная структура из 3b
  была бы видна по входящей степени, если бы её логировали
- **длинные разрывы > 64** — `gens.long` (T=40) и флаг `--eval_gen` добавлены, но ни один
  чекпоинт на них ещё не прогонялся
- **масштаб** — все выводы получены на 12C/388K/SDQ; переносится ли это на `_2m`/`_10m`
  и на text8, где `aux_act` теперь тоже включился
