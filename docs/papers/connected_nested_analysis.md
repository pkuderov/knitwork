## 1. It's All Connected: A Journey Through Test-Time Memorization, Attentional Bias, Retention, and Online Optimization

**arXiv: 2504.13173 · Апрель 2025**

### Центральная идея

Статья утверждает, что Transformer'ы, линейные RNN (Mamba, RetNet, RWKV) и Titans — это частные случаи одного и того же механизма: **ассоциативной памяти, обучаемой во время инференса** (test-time memorization). Все они решают задачу «запомнить отображение ключ → значение» с помощью одного и того же уравнения, различаясь только в трёх выборах: что оптимизировать, как забывать, каким алгоритмом обновлять.

### Фреймворк Miras: 4 оси дизайна

Каждая архитектура однозначно задаётся комбинацией:

**1. Структура памяти** — насколько выразительный контейнер для хранения:
- Вектор (RetNet-style)
- Матрица (Mamba, DeltaNet, GLA)
- MLP-сеть k слоёв (Titans, TTT)

**2. Attentional bias** — внутренняя цель, которую память оптимизирует на каждом шаге:

*Dot-product / Hebbian (RetNet, Mamba):*
$$\tilde{\ell}_t = -2\langle\mathcal{M}_t\mathbf{k}_t, \mathbf{v}_t\rangle$$
Быстро, параллелизуемо, но ограниченная ёмкость.

*L2-регрессия / Delta rule (DeltaNet, RWKV-7, Titans):*
$$\mathcal{L} = \|\mathcal{M}(\mathbf{k}_t) - \mathbf{v}_t\|_2^2$$
Явная реконструкция → более высокая ёмкость.

**3. Retention gate** — как сохраняется прошлое (не «забывание», а регуляризация):
$$\text{Ret}_t(W, W_{t-1}) = \frac{1}{\eta_t}\mathbf{D}_t(W, W_{t-1}) + \frac{1}{\alpha_t}\mathbf{G}_t(W)$$
- $\mathbf{D}_t$ — локальный retention: отклонение от предыдущего состояния
- $\mathbf{G}_t$ — глобальный retention: ограничение общей нормы весов
- Ключевое переосмысление: «забывание» — это не выбрасывание, а регуляризация, поддерживающая устойчивость

**4. Алгоритм обучения** — как цели превращаются в обновления весов памяти:
- Градиентный спуск (стандартно)
- SGD с моментом (→ Titans)
- Неявный градиентный спуск
- Метод Ньютона

### Теоретическое объединение

Две эквивалентные формулировки (Proposition 3.2):

**FTRL:** $W_t = \arg\min_W \sum_{i=1}^t\hat{\ell}_i(W) + \frac{1}{\eta_t}\mathcal{R}_t(W)$

**Learning-Retaining:** $W_t = \arg\min_W \tilde{\ell}_t(W) + \text{Ret}_t(W, W_{t-1})$

Эквивалентность достигается через дивергенцию Брегмана — математически объединяя архитектуры, которые казались несвязанными.

### Новые модели (Moneta, Yaad, Memora)

Авторы показывают, что пространство Miras не исчерпано существующими моделями, и предлагают три новых:

| Модель | Attentional bias | Retention | Ключевое свойство |
|---|---|---|---|
| **Moneta** | $L_p$-норма | $L_q$ | Устойчивость к не-гауссовому шуму |
| **Yaad** | Huber loss | $L_2$ | Гибридная L1/L2 робастность |
| **Memora** | $L_2$ | KL-дивергенция | Работа в пространстве вероятностей |

**Moneta** использует аккумулятор $A_t$, нормализованный $L_q$-нормой, что делает обновление устойчивым к выбросам.

**Yaad** динамически переключается: если ошибка предсказания мала — L2-шаг, иначе — L1-шаг. Аналог Huber loss в пространстве обновлений памяти.

**Memora** обновляется в лог-пространстве с softmax: $W_t = \text{Softmax}(\alpha_t\log(W_{t-1}) - \eta_t\nabla\ell_2)$. Веса всегда неотрицательны, что полезно для задач с длинным хвостом.

### Связь с Grid RNN

Grid RNN реализует похожую идею: каждая колонка — это «память» определённого уровня абстракции, а attention между колонками — это механизм передачи ключей и значений. Формализм Miras позволяет:

1. **Переосмыслить gate `g`** в post-messaging как retention gate: насколько колонка принимает сообщение = насколько старое состояние «регуляризуется» новой информацией
2. **Интерпретировать `grnn_delta.py`** как Delta-rule attentional bias — явно в терминах Miras это L2-регрессия с GD
3. **Предложить новые варианты**: заменить L2 retention на KL (→ Memora-style GridRNN) или использовать Huber-bias (→ Yaad-style)

## 2. Nested Learning: The Illusion of Deep Learning Architectures

**arXiv: 2512.24695 · NeurIPS 2025**

### Центральная идея

Статья предлагает взглянуть на глубокое обучение иначе: любая архитектура — это **иерархическая вложенная оптимизация**, где каждый уровень компрессирует собственный «поток контекста» (context flow). Глубина сети — это не просто стэкинг слоёв, а явная метаструктура: слои высокого уровня оптимизируют то, как учатся слои низкого уровня.

### Что такое context flow

Context flow — информационный поток, который каждый оптимизационный уровень видит на входе и трансформирует. В стандартной сети:
- Уровень 0: получает сырые данные (x, y) — это его context flow
- Уровень 1: получает градиенты от уровня 0 — его context flow
- Уровень k: получает агрегированную информацию об истории обучения уровня k-1

Ключевое утверждение: **in-context learning** Transformer'ов — это естественное следствие такой иерархии, а не особое свойство архитектуры.

### Deep Optimizers

Авторы переосмысляют классические оптимизаторы как **модули ассоциативной памяти, компрессирующие градиенты**:

- SGD с моментом → RNN с одним скрытым состоянием (аккумулятор момента)
- Adam → RNN с двумя состояниями (первый и второй моменты)
- Адаптивные оптимизаторы → более сложные рекуррентные структуры

Из этого следует: оптимизатор можно **обучать** (meta-learning), заменив ручной алгоритм на параметрическую рекуррентную сеть. Deep Optimizer — это оптимизатор с обучаемой рекуррентностью, где контекст — история градиентов.

### Continuum Memory System (CMS)

CMS обобщает LSTM-подобные long/short-term механизмы в непрерывную иерархию:

- Вместо двух шкал времени (short/long) — **континуум временных масштабов**
- Каждый блок памяти обновляется с разной скоростью: от быстрых (per-token) до медленных (per-epoch)
- Формально: $M_k(t) = \alpha_k M_k(t-1) + (1-\alpha_k) f_k(x_t)$, где $\alpha_k$ различается по уровням

Это напрямую аналогично тому, как `grnn_lru.py` использует разные `r_max` для колонок: медленная колонка → большой $\alpha$ → долгосрочная память.

### HOPE: Self-Modifying Architecture

HOPE (self-modifying Titans) объединяет CMS с механизмом самомодификации: модель обновляет свои веса в процессе инференса (test-time learning), используя градиенты от внутренней цели (attentional bias).

Результаты: улучшение в:
- Language modeling (perplexity)
- Few-shot generalization
- Continual learning (устойчивость к catastrophic forgetting)
- Long-context reasoning

### Ключевое философское утверждение

«Глубокое обучение — это иллюзия»: модель не просто «глубокая», она реализует **метаобучение** — каждый слой учит следующий, как учиться. Традиционные архитектуры делают это неявно; Nested Learning делает это явным.

### Связь с Grid RNN

| NL концепт | Аналог в Grid RNN |
|---|---|
| Context flow | Поток сигнала через колонки (каждая колонка обрабатывает свой «поток») |
| Deep Optimizer | `grnn_eq.py` — итеративная сходимость как внутренняя оптимизация |
| CMS (multi-timescale) | `grnn_lru.py` с `lru_r_per_col=True` — разные $r_{max}$ на колонку |
| HOPE (self-modifying) | `grnn_delta.py` — Delta rule = test-time weight update |

Grid RNN реализует «ширину» Nested Learning (параллельные колонки с разными timescales), но не «глубину» в смысле NL (нет явной метаоптимизации уровней).

## 3. Синтез: что обе статьи говорят для Grid RNN

### Общий знаменатель

Обе статьи сходятся в одной идее: **архитектура = выбор функции потери памяти + алгоритм её минимизации + механизм удержания контекста**. Разные архитектуры — это разные точки в этом пространстве.

Grid RNN как фреймворк уже содержит аналоги всех трёх компонент:
- **Функция потери памяти** ↔ attentional bias в attention между колонками
- **Алгоритм** ↔ GRU/LRU update rule в каждой колонке
- **Удержание** ↔ gate `g` в post-messaging

### Конкретные направления

1. **Проверить Delta-rule (grnn_delta.py) через линзу Miras**: это L2-регрессия с GD — самый исследованный вариант. Добавление Huber-bias или KL-retention — следующий логичный шаг.

2. **CMS как явная разница timescales**: Grid LRU с `lru_r_per_col` уже делает это. Усилить: сделать $\alpha_k$ обучаемыми per-column параметрами, а не фиксированными через $r_{max}$.

3. **Test-time memorization в Grid RNN**: возможность обновлять веса части колонок во время инференса (как HOPE) — потенциальная новая архитектура `grnn_ttl.py` (test-time learning columns).

4. **Retention как регуляризация**: gate `g` можно переосмыслить как обучаемый retention coefficient. Добавление KL-регуляризации между последовательными состояниями колонок может улучшить стабильность.
