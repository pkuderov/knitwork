# HarmonicGridRNN

## Описание

**HarmonicGridRNN** — гармоническая Grid RNN, объединяющая четыре смысловых блока в единую архитектуру. Название отражает идею «гармоник»: каждый блок работает на своей «частоте» и усиливает остальные — как обертоны акустического сигнала складываются в богатый звук. Цель модели — преодолеть ограничения существующих архитектур: `hgrnn_lru` отлично работает на SDQ, но нестабильна в RL; `grnn_ema_mem` выигрывает в MIKASA, но слабее в ассоциативных задачах; `grnn_delta` теоретически верна, но не обучается из-за сложности оптимизации. Гармоническая модель объединяет лучшее из каждой, не наследуя их слабостей.

## Четыре блока

| # | Блок | Обучаем? | Роль |
|---|------|---------|------|
| 1 | Spectral LRU | ✓ | 2D иерархия временны́х масштабов |
| 2 | Surprise-Delta Memory | ✓ | Адаптивная KV-память без интерференции |
| 3 | Frozen Reservoir | ✗ | Долгосрочный контекст (текст) |
| 4 | Hopfield Integration | ✓ | Резкая кросс-колоночная ассоциативная выборка |

## Ключевые механизмы

### Block 1: Spectral LRU

Каждая колонка и каждый слой имеют собственный `r_max`, формируя 2D спектральную сетку. Нижние слои и левые колонки — быстрые (низкий r), верхние и правые — медленные (высокий r). Это обеспечивает представления на разных временны́х масштабах без дополнительных параметров.

```python
# r_max[layer, col] = r_min_col + (r_base_layer - r_min_col) * (col / (C-1))
# r_base_layer интерполирован от r_min_layers до r_max_layers
```

### Block 2: SurpriseDeltaMemory — ключевой новый модуль

Объединяет принципы из `grnn_ema_mem` (EMA-гейт записи) и `grnn_delta/prec_delta` (дельта-правило). Пишет в общую матрицу `W [B, dk, dv]` пропорционально ошибке предсказания, используя дельта-правило для устранения интерференции.

```python
# 1. Параллельное дельта-правило на замороженном W (нет chained Jacobians):
v = F.normalize(proj_v(y), dim=-1)  # нормировано → ||delta_W||_F ограничен
v_pred = W.T @ k[c]
error  = v[c] - v_pred              # ошибка предсказания ∈ [-2, 2]
delta_W += k[c] ⊗ error             # outer product

# 2. EMA surprise — отслеживает "насколько неожиданным" был ввод:
m_new = ema_beta * m + (1-ema_beta) * mean(error²)
alpha = (m_new / max(m_new + eps)).clamp(0, 1)  # нормировка по батчу; нет заморозки

# 3. Adaptive forgetting (из grnn_ema_mem):
fullness = ||W||_F / sqrt(dk * dv)
lam = lam_base * fullness.clamp(0, 1)

# 4. Delta update (per-layer delta_decay: 0.95 → 0.99):
W_new = (1-lam) * delta_decay[layer] * W + alpha * delta_W
```

**Ключевое отличие от `grnn_delta`**: один масштаб памяти, EMA-гейт вместо per-column sigmoid, shared W (не per-column) → значительно проще оптимизировать. Ключевое отличие от `grnn_ema_mem`: дельта-правило исправляет старые ассоциации, Hebb только добавляет → нет интерференции.

**Числовая стабилизация (v2)**:
- `delta_W /= C` — критически важно: без нормировки на C эффективный eigenvalue матрицы обновления = `decay - alpha*C = 0.99 - 4 = -3.01` → W взрывается с коэффициентом 3 каждый шаг. С `/C`: eigenvalue = `decay - alpha = -0.01` → сходится.
- v нормируется (F.normalize) → начальный delta_W ограничен
- alpha = m / max(m) вместо sigmoid(log(m)) — нет заморозки записей при m≈0
- `out_norms[l]` — inter-layer LayerNorm предотвращает рост h между слоями
- per-layer delta_decay: нижние слои забывают быстрее (0.95), верхние — медленнее (0.99)

### Block 3: Frozen Reservoir

Фиксированные случайные RNN-колонки с разными спектральными радиусами (от `r_res_min` до `r_res_max`). При `r=0.999` время памяти ≈ 1000 шагов — охватывает предложение/абзац в тексте.

```python
h_res[c] = r[c] * h_res[c] + (1-r[c]) * tanh(W_fixed[c] @ x)  # W_fixed заморожен
y_res[c] = res_proj[c](h_res[c])   # обучаемая проекция [H_res → H]
```

Резервуар выступает **read-only** источником долгосрочного контекста для Hopfield attention. В SDQ-задачах (короткие последовательности) отключается (`n_reservoir_cols=0`).

### Inter-layer normalization

После каждого слоя `y_out` нормируется (LayerNorm) перед подачей в следующий слой:
```python
y_out = out_norms[l](y_out)  # [C, B, H] — предотвращает экспоненциальный рост магнитуды
```
Без этой нормировки три слоя без стабилизации между ними приводят к Inf в логитах (~10M шагов).

### Block 4: Hopfield Cross-Column Integration

Modern Hopfield Networks с learnable β per head — как в `hgrnn_lru`. Принимает на вход все обучаемые колонки + проекции резервуара. Гейт применяется только к обучаемым колонкам.

```python
all_cols = cat([y_aug[C], y_res[C_res]])   # [C+C_res, B, H]
msgs, attn = HopfieldMessageLayer(all_cols)
msgs_train = msgs[:C]
y_out = (1-g) * y_aug + g * msgs_train     # gated merge
```

### Embedding Residual Skip

После каждого LRU-блока добавляется проекция исходного эмбеддинга:
```python
y_lru = y_lru + embed_skip[l](x_embed)
```
Создаёт прямой путь градиента от функции потерь до эмбеддинга на каждом слое.

## Гиперпараметры

- `r_min_col` (0.3), `r_min_layers` (0.7), `r_max_layers` (0.999) — границы 2D спектральной иерархии
- `dk` / `dv` — размерности ключей/значений памяти (по умолчанию H//4 и H)
- `ema_beta` (0.9) — быстрое EMA (~10 шагов); 0.99 = медленное (~100 шагов); чувствительный параметр для RL
- `delta_decay` (0.99) / `delta_decay_min` (0.95) — максимальный и минимальный decay W; интерполируются по слоям: нижние слои забывают быстрее
- `lam_base` (0.01) — базовая скорость забывания; 0.1 = агрессивное, 0.001 = почти нет
- `n_reservoir_cols` (0 для SDQ/RL, 4 для текста) — отключить резервуар для коротких задач
- `reservoir_hidden_size` (64) — размерность резервуара; не влияет на скорость при n_reservoir_cols=0
- `r_res_max` (0.999) — наибольший спектральный радиус резервуара; ≈1000 шагов памяти

## Состояние

```python
HarmonicState(
    h:     [L, C, B, 2H]        # LRU-состояния (Re | Im); Im часть детачится
    h_res: [L, C_res, B, H_res] # резервуар; всегда детачится
    W:     [L, B, dk, dv]       # матрица дельта-памяти
    m:     [L, B]               # EMA surprise per layer
)
```

## Результаты экспериментов

### SDQ (grnn_harmonic, 2.11M params, 3L×4C, нет резервуара)

Эксперимент запущен 2026-06-09, остановлен на 228M шагах из 1000M.

| Шаг | Loss | Acc | Acc/query | Acc/distract |
|-----|------|-----|-----------|--------------|
| 5M  | 1.331 | 0.504 | 0.228 | — |
| 25M | NaN   | **0.741** | **0.509** | — |
| 100M | NaN  | 0.577 | 0.411 | 0.688 |
| 228M | NaN  | 0.385 | 0.291 | 0.447 |

Loss переходит в NaN с шага ~10M. Accuracy при этом остаётся вычислимой (не зависит от loss), достигает пика ~0.74 на 25M, затем постепенно деградирует — из-за пропуска всех обновлений оптимизатора при бесконечном grad_norm.

### Text (grnn_harmonic, 2.22M params, 3L×4C, 4 резервуарных колонки)

| Шаг | BPC | Acc |
|-----|-----|-----|
| 5M  | NaN | 0.036 |
| 228M | NaN | 0.036 |

Loss и BPC NaN с первого батча. Accuracy остаётся на уровне случайного угадывания (1/27 ≈ 0.037). С резервуарными колонками NaN возникает раньше, чем без них.

### Вывод

Основная проблема — NaN/Inf gradients с первых шагов обучения. Применённые исправления (F.normalize в Hopfield, sigmoid(log(m)) в дельта-памяти) не устранили проблему полностью. Вероятные оставшиеся источники: LRU комплексные экспоненты при больших активациях, кросс-колоночное Hopfield внимание с нелинейным beta. Для следующего запуска необходима диагностика с `torch.autograd.set_detect_anomaly(True)` на малой модели.
