# Краткие особенности вариантов коммуникации и памяти

Названия относятся к разным сериям. Grid-LRU из H100-отчёта и локальные GRU-контроли имеют разные ячейки и routers; одно похожее имя не означает одинаковую реализацию.

| Серверный Grid-LRU | Особенность |
|---|---|
| `control` | Все колонки читают все источники; обучаемые веса обмена не зависят от текущего содержимого. |
| `self-heavy` | Те же связи, но начальный вес собственной колонки у периферии равен 70%; это инициализация, а не фиксированный коэффициент на всё обучение. |
| `star` | Периферийная колонка читает себя и центр; центр читает всех. |
| `star-ring` | К star добавляется чтение одного соседа по направленному кольцу периферии. |
| `clockwork` | Колонки 0/1 обновляются каждый шаг, 2/3 — через шаг поочерёдно; communication products остаются dense. |
| `block` | Входные и выходные проекции LRU разбиты на две группы каналов, между слоями каналы переставляются; связи между колонками остаются dense. |
| `entmax` | На периферии entmax позволяет получать ровно нулевые веса; центр сохраняет softmax. Начальная диагональная настройка также смягчена. |
| `dynamic_hub` | Star-связи, но центр выбирает источники по текущему контексту через Q/K размерности 8; периферийные маршруты остаются content-independent. |
| `dynamic_control` | Опорная модель архитектурных ablation: star + dynamic hub с нулевой инициализацией Q-проекции. |
| `write_gate` | Центр управляет долей обновления каждой периферийной памяти; используются gates между старым и новым состоянием. |
| `query_read` | Центр получает чтение из приватного LRU-state периферии через узкие проекции размерности 16, управляемые текущим контекстом. |
| `associative` | Колонка 3 заменяется матрицей памяти 16 × 32 на слой, с обучаемой записью и чтением по ключу. |
| `rotations` | Состояния центра и периферии дополнительно смешиваются последовательными обучаемыми поворотами; углы начинают с нуля. |
| `two_reads` | После первого обновления центр читает свежие сообщения и пересчитывает собственное обновление из своего прежнего состояния; периферия обновляется один раз. |

Для self-heavy нижний слой начинает с 70% своего feedback, 15% внешнего ввода, 15% остальных колонок; верхний — 70% своей колонки и 30% остальных. Колонка 0 сохраняет обычную инициализацию. Star и star-ring в использованных конфигурациях не включают self-heavy. В star-ring колонка 1 читает 2, колонка 2 читает 3, колонка 3 читает 1. Внешний ввод нижнего слоя доступен всем. Разрешённые коэффициенты обучаются; запрещённые связи остаются закрытыми. Предсказание всех перечисленных серверных Grid-LRU читает колонку 0.

| Остальные серверные ablation | Особенность |
|---|---|
| `top-1` / `top-2` | Dynamic-attention Grid-GRU сохраняет один/два наиболее подходящих источника для каждого получателя и головы. Dense-проекции продолжают вычисляться. |
| `rollout 64` / `512` | Меняется длина backpropagation; при одинаковых tokens/update меняется и число параллельных потоков 512→64. |
| `full` | Исходный рецепт: routing noise + communication penalty + entropy bonus. |
| `no_noise` | Убран шум маршрутизации. |
| `no_comm_penalty` | Убран штраф коммуникации; сам обмен сохранён. |
| `no_entropy` | Убран entropy bonus. |
| `no_aux` | Убраны шум и оба вспомогательных слагаемых; межколоночный обмен сохранён. |
| `noise_only` / `comm_only` / `entropy_only` | Оставлена только соответствующая одна добавка; определения доступны в конфигурациях, включение в результаты определяется наличием завершённого запуска. |

| Локальные GRU-контроли | Особенность |
|---|---|
| `dynamic_column0` | Межколоночный attention зависит от содержимого; читается верхняя колонка 0. |
| `dynamic_mean` | Тот же dynamic-router; читается среднее четырёх верхних состояний. |
| `static_column0` | Q/K зависят только от обучаемых идентичностей; читается колонка 0. |
| `static_mean` | Тот же content-independent router; читается среднее верхних состояний. |
| `none_column0` | Межколоночный обмен запрещён; в исходном L2C4 остальные колонки не имеют пути к предсказанию. |
| `none_mean` | Колонки независимы, но предсказание использует среднее всех четырёх верхних состояний. |
| `none_column0`, L2C1 | Единственный столбец с двумя GRU и H228; нет неиспользуемых столбцов, все 456 state-значений доступны предсказанию. |
| `none_concat` | Четыре независимых столбца L2C4/H136; линейная prediction head читает concat длиной 544. State остаётся 1088. |

## Block на маленьком примере

Пусть одна LRU-ячейка имеет восемь признаков. Полная входная проекция использует любую из восьми входных координат для каждой из восьми комплексных координат памяти, то есть матрицу 8 × 16. С двумя blocks входы x0…x3 обрабатывает первая матрица 4 × 8, входы x4…x7 — вторая 4 × 8. Получается 64 веса вместо 128. Выходная проекция тоже меняется с 16 × 8 на две 8 × 4. Само комплексное recurrent state остаётся прежнего размера: восемь действительных и восемь мнимых координат.

После нижнего слоя выход `[a0 a1 a2 a3 | b0 b1 b2 b3]` переставляется в `[a0 b0 a1 b1 | a2 b2 a3 b3]`. Первые четыре координаты следующего слоя теперь содержат признаки обеих прежних групп. Channel shuffle не обучается и не добавляет параметров. В реальном варианте H180 группы имеют размер 90; полная входная матрица 180 × 360 заменяется двумя 90 × 180, а выходная — аналогичными двумя меньшими матрицами. Число параметров этих проекций уменьшается вдвое. Такое разбиение применяется внутри каждой колонки; dense communication между колонками сохраняется.

Центр в star-схемах — колонка 0 каждого слоя; она имеет собственную память и читает все источники. Предсказание использует верхнюю колонку 0. Dynamic hub добавляет центру запрос/ключи размерности 8 для выбора источников по текущему контексту. Rotations перед обновлением LRU последовательно смешивает состояния центра и каждой периферийной колонки по формулам `c′ = c cosθ + p sinθ`, `p′ = −c sinθ + p cosθ`; обучаемые углы начинают с нуля.

## Associative на маленьком примере

Вместо LRU-состояния колонки 3 каждый слой хранит для каждого потока матрицу M размерности 16 × 32. Она начинается с нулей и сбрасывается при начале новой последовательности. На каждом шаге линейная write-проекция сообщения этой колонки формирует key k из 16 чисел, value v из 32 и скаляр силы записи α. Key нормируется, value проходит tanh, α — sigmoid. Старое значение читается как r = Mᵀk; затем память корректируется по ошибке записи: M_new = M + α k(v − r)ᵀ. Проекции и сила записи обучаются градиентами задачи; M является recurrent state, а не обычной фиксированной матрицей весов.

Для чтения отдельная проекция контекста центра строит нормированный запрос q из 16 чисел. Вектор Mᵀq из 32 чисел проецируется в сообщение длиной 180. В star-router центр может использовать это сообщение. После записи новая матрица также даёт публичный выход колонки 3 через SiLU и residual добавление входящего сообщения. Остальные три колонки сохраняют обычные LRU.

В условном случае памяти 2 × 2 и полной записи key [1,0] / value [0.2,0.8] заполняют первую строку; key [0,1] / value [0.7,−0.1] — вторую. Запрос [1,0] возвращает первое значение. Реальные ключи непрерывные и не обязательно ортогональны: похожие ключи могут мешать друг другу. Шестнадцать строк задают размер пространства ключей, а не шестнадцать отдельных дискретных записей.
